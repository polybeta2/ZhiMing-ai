# ZhiMing v2.0.0 三项优化实施计划

## 概述

1. **撰写按钮**：章节字数为 0 时「续写」变「撰写」，可选目标字数 1500~4500（步进 500），无细纲时提醒先生成细纲；新增「撰写」专用提示词。
2. **立项流程重构**：一句话立项改为分阶段交互式流程：澄清提问 → 确定卷数/章节数 → 生成卷纲+基础设定 → 对话内逐批生成细纲（每轮 1~3 章可设置，支持自动连续），可随时「创建作品」落库（未生成细纲的章节留空，之后可在「大纲」页补充）。
3. **AI 生成过程可视化**（全部生成场景接入）：等待首 Token 计时「正在等待首Token Xs」、思维链摘要「深度思考 X字 Xs」（不显示思维链原文）、JSON 输出期间「正在输出 X字 Xs」（输出完成后才展示表格/卡片）。
4. 完成后发布 v2.0.0（构建、提交、tag、GitHub Release + ipa 资产）。

**实施顺序**：功能 3 底层 → 功能 3 各场景接入 → 功能 1 → 功能 2（立项 JSON 流式展示依赖功能 3）→ 构建 → 发布。

## 功能 3：AI 生成过程可视化（先行）

### 3.1 流式层：StreamEvent + reasoning_content 解析

**`Sources/ZhiMing/Services/LLMClient.swift`**
```swift
enum StreamEvent {
    case reasoning(String)   // 思维链 delta（reasoning_content / reasoning）
    case content(String)     // 正文 delta
}
```
- `LLMClient.streamChat` 返回类型改为 `AsyncThrowingStream<StreamEvent, Error>`。

**`Sources/ZhiMing/Services/OpenAICompatibleClient.swift`**
- `extractDelta` → `extractEvents`：从 `choices[0].delta` 中解析 `reasoning_content`（兼容字段名 `reasoning`）与 `content`，各自非空时 yield 对应事件（一帧可能两者都有，返回小数组）。
- `testConnection`：只累计 `.content`。

### 3.2 通用进度跟踪器（新文件 `Sources/ZhiMing/Services/StreamProgressTracker.swift`）

```swift
@MainActor
final class StreamProgressTracker: ObservableObject {
    enum Stage: Equatable { case idle, waitingFirstToken, thinking, outputting }
    @Published private(set) var stage: Stage = .idle
    @Published private(set) var reasoningChars = 0
    @Published private(set) var contentChars = 0
    @Published private(set) var elapsed: TimeInterval = 0   // 当前阶段耗时
}
```
- API：`begin()`（→ waitingFirstToken，启动 0.1s Timer 刷新 elapsed）、`handle(_ event: StreamEvent)`（首个事件离开 waiting；reasoning 累加且 → thinking；content 累加且 → outputting）、`finish()`（→ idle，停表）。
- 各阶段 elapsed 从该阶段开始计时：等待首Token=请求起到首事件；深度思考=首事件起到首个 content；输出=首 content 起。

### 3.3 状态显示组件（新文件 `Sources/ZhiMing/Views/Shared/StreamingStatusView.swift`）

- `StreamingStatusView(tracker:)`：一行式胶囊（ProgressView 小圈 + 文本）：
  - `waitingFirstToken` → 「正在等待首Token 3.2s」
  - `thinking` → 「深度思考 1284字 6.5s」
  - `outputting` → 「正在输出 3560字 12.1s」（仅当调用方选择隐藏内容时显示此形态；正文流式场景调用方传 `outputtingLabel: false` 则 outputting 阶段不渲染本组件）
- monospacedDigit 字体，Apple 风格克制样式（caption + secondary）。

### 3.4 各场景接入

| 场景 | 位置 | 做法 |
|---|---|---|
| 章节续写/撰写/改写草稿 | `WritingSessionViewModel` + `DraftCard` | VM 增加 `let progress = StreamProgressTracker()`；`beginStreaming` 循环改为消费 `StreamEvent`，reasoning 只进 tracker，content 进 draft；DraftCard 在 streaming 且 `progress.stage != .outputting` 时顶部显示 StreamingStatusView（outputting 阶段正文正常流式展示） |
| 立项各阶段 JSON 生成 | `CreationSessionViewModel` + `ChatView` | VM 挂 tracker；**流式期间 ChatView 不再镜像 draft 文本到气泡**，改为在消息流尾部显示 StreamingStatusView（全程三种状态轮转），流结束才展示结构卡/蓝图卡/气泡摘要 |
| 写作助手普通对话 | `ChatView.startWritingReply` | 该方法内联的流式循环改为消费 StreamEvent 并喂给 ChatView 持有的 tracker；气泡区：waiting/thinking 阶段显示 StreamingStatusView（不显示气泡文本），outputting 阶段恢复现有流式文本气泡（`streamingText` 只累计 content） |
| 卷纲/细纲草稿（大纲页） | `OutlineAssistViewModel` + `OutlineView` | VM 挂 tracker；生成草稿区域 streaming 时显示 StreamingStatusView |
| 章节摘要 | `ChapterEditorView.generateSummary` | 现有「正在生成章节摘要…」行升级：挂 tracker，显示字数/秒 |

**注意**：`ChatView` 中 `observeCreationStream`（80ms 轮询镜像 draft）在立项 JSON 场景删除，改为 tracker 驱动；`settleCreation` 逻辑保持。

## 功能 1：撰写按钮

### 1.1 UI（`ChapterEditorView.swift`）

- 工具条按钮动态化（L172）：`toolButton(text.count == 0 ? "撰写" : "续写", icon: "square.and.pencil")`；两者点击都设 `showContinueSheet = true`。
- `ContinueWritingSheet` 增加 `isNewChapter: Bool`：
  - `true`：标题「AI 撰写」；字数选项 `[1500, 2000, 2500, 3000, 3500, 4000, 4500]`（7 档用默认 menu 样式 Picker，segmented 放不下）。
  - `false`：维持现状（segmented 800/1500/2500）。
- 无细纲提醒：`isNewChapter && chapter.detailedOutline 为空` 时，Sheet 顶部 Section 显示橙色提示行：「本章还没有细纲，撰写质量会大打折扣。建议先到「大纲」页生成本章细纲。」（提醒但不阻断，可继续生成）。
- `startContinue` 增加参数区分模式，传给 VM。

### 1.2 ViewModel（`WritingSessionViewModel.swift`）

- `Mode` 增加 `case writing(wordTarget: Int)`。
- `start()` 中 `.writing` 分支：复用 `ContextBuilder.buildContinueContext`（content 为空时正文末尾段自然为空，无需改 ContextBuilder），消息装配改调 `PromptTemplates.writing(...)`。
- `lastContinue` 元组增加模式标记，`regenerate`/`DraftCard` 采纳链路沿用（撰写采纳=覆盖空正文，`accept(into:)` 追加语义等价）。

### 1.3 提示词

- `PromptID.writing = "prompt.writing.system"`；`makeBuiltInPrompts()` 登记「撰写 · 系统提示词」，默认文本要点：
  - 基于本章细纲从零撰写**完整一章**，以细纲为纲、覆盖全部要点；
  - 直接入戏，禁止复述梗概/细纲、禁止写章节标题与「本章」类元话语；
  - 遵循风格约束与视角，正文一次性成章，目标字数 ±15%。
- `PromptTemplates.writing(context:wordTarget:extra:)`：结构与 `continueWriting` 对称，用户侧文案改为「请撰写约 N 字的完整章节」。

## 功能 2：立项流程重构

### 2.1 新状态机（`CreationSessionViewModel.swift` 重构）

Phase 重新设计（streaming 改为独立发布属性，phase 只表达流程位置）：

```swift
enum Phase: Equatable {
    case collecting     // 收集创意 / 回答澄清问题
    case proposing      // 结构提案待确认
    case blueprintReady // 基础蓝图就绪（可修订 / 可进入细纲 / 可创建）
    case outlining      // 细纲批次进行中（含自动连续）
    case confirmed
}
@Published private(set) var isStreaming = false
```

流程转换：
1. **collecting**：用户发创意 → `requestClarify`（携带创意+已有多轮问答）→ 解析 `ClarifyResult`：
   - `enough == false`：问题列表以助手气泡展示（编号列表），留在 collecting 等回答；用户回答 → 再次 `requestClarify`（循环）。
   - `enough == true`：自动接 `requestStructure` → `proposing`。
2. **proposing**：结构提案（详细思路 + 卷/章规划）展示为卡片；「确认结构」→ `requestFoundation` → `blueprintReady`；用户发文字 = 修改意见 → 重新 `requestStructure`。
3. **blueprintReady**：现有 `BlueprintCardsView` 展示可编辑蓝图；「开始生成细纲」→ `outlining`；用户发文字 = 修订意见（复用 `creationRevise`，携带当前完整蓝图含已生成细纲，AI 保留未涉及字段）。
4. **outlining**：每轮生成下一批 1~3 章细纲；批次完成写入蓝图对应章节；`autoContinue` 开启且仍有未完成章节时延迟 1s 自动下一批；全部完成或用户点「创建作品」/停止 → 结束。
5. 任意 `blueprintReady`/`outlining` 状态可「创建作品」→ 现有 `confirm(into:store:)` 落库（细纲为空的章节 `detailedOutline` 留 nil，提示用户可在「大纲」页补充生成）。

### 2.2 新增 Codable 结构（放 `CreationSessionViewModel.swift`）

```swift
struct ClarifyResult: Codable { var enough: Bool; var questions: [String]; var reason: String? }
struct StructureProposal: Codable {
    var concept: String                        // 详细思路（Markdown 文本，气泡展示）
    var volumes: [ProposedVolume]              // 卷章规划
    struct ProposedVolume: Codable { var name: String; var chapter_count: Int }
}
```
批次细纲复用现有 `BlueprintChapter`。

### 2.3 新提示词（`PromptLibrary.swift` 登记 + `PromptTemplates.swift` 装配）

| PromptID | 名称 | 输入 | 输出 |
|---|---|---|---|
| `prompt.creation.clarify.system` | 立项澄清提问 | 创意 + 已有问答 | JSON `{enough, questions[], reason}`；参照 `docs/novel-outline-architect.md` 的缺口判断原则（已讲清的不问、问题一次性打包、用户已委托决定的不再问） |
| `prompt.creation.structure.system` | 立项结构规划 | 创意 + 问答 | JSON：`concept`（详细思路，含类型/篇幅/主角/世界观/主线/结局/视角/文风/感情线）+ `volumes[]`（卷名+每卷章数） |
| `prompt.creation.foundation.system` | 立项基础蓝图 | 创意 + 问答 + 结构 | 复用现有 blueprint JSON schema，**chapters 只给 title，不给 detailed_outline/scene_cards**；卷纲完整（含四维） |
| `prompt.creation.chapter.batch.system` | 细纲批量生成 | 基础蓝图摘要 + 卷纲 + 已生成细纲摘要 + 目标章节列表（1~3章标题） | JSON：这些章节的 `[{title, detailed_outline, scene_cards}]` |
| 保留 `creationRevise`（修订场景不变）；**移除 `creationBlueprint`（一步全生成）的调用**，BuiltInPrompt 条目一并删除 |

### 2.4 UI（`ChatView.swift` 立项分支 + 新子视图）

- **阶段指示**：`creationActions` 区域顶部加阶段标签（思路 → 结构 → 蓝图 → 细纲 → 完成），当前阶段高亮。
- **澄清问题**：助手气泡展示（文本编号列表），输入框 placeholder 不变。
- **结构提案卡**（新 `StructureProposalCard`）：详细思路文本 + 卷/章数列表（每卷行：卷名 + N 章）+「确认结构」按钮。
- **细纲控制卡**（新 `OutlineBatchControls`，`blueprintReady`/`outlining` 时显示）：
  - 进度行「细纲进度 X/Y 章」；
  - 每轮章数 Picker（1/2/3）+ 自动连续 Toggle；
  - 「生成下一批细纲」按钮（outlining 且自动模式中变为「停止自动」）；
  - 批次完成：助手气泡「已生成第X~Y章细纲」+ BlueprintCardsView 就地刷新。
- **「创建作品」按钮**：`blueprintReady` 起常驻；`confirm` 后追加气泡提示「未生成细纲的章节可在『大纲』页补充」。
- **流式期间**：统一显示 StreamingStatusView（功能 3），不显示原始 JSON。
- `NovelCreateSheet` 一句话立项副标题更新：「分阶段共创：理清思路 → 卷章结构 → 卷纲 → 细纲」。

### 2.5 关键实现细节

- 下一批章节定位：按卷序/章序扫描 `blueprint.volumes`，取前 N 个 `detailed_outline` 为空的章节。
- 修订与细纲共存：`outlining` 中用户发消息 → 取消自动连续，按 `blueprintReady` 的修订路径处理（完整蓝图含已生成细纲一起发送）。
- `stop()`：取消当前流 + 关闭自动连续；已生成批次保留。
- 旧 `routeCreation`/`settleCreation` 按新 phase 重写路由；`onStreamSettled` 模式保留。
- 会话不持久化进度（与现状一致：ViewModel 内存态，thread.messages 持久化对话文本）。

## 假设与决策

- 思维链字段按 OpenAI 兼容事实标准解析 `reasoning_content`，兼容 `reasoning`；不显示思维链原文，仅统计。
- 「正在输出 X字 Xs」仅在 JSON/静默场景使用；正文流式场景 outputting 阶段正常显示文本。
- 撰写字数 7 档用 menu Picker（segmented 放不下）；续写档位维持现状。
- 无细纲提醒为非阻断提示（Sheet 内橙色 Section），不强导航。
- 立项旧「一步全生成」流程彻底替换，不做兼容开关；`creationBlueprint` 提示词条目删除。
- 未生成细纲的章节创建后 `detailedOutline == nil`，「大纲」页既有 OutlineAssistViewModel 单章生成能力天然支持补充。
